# 2026.311.0316 — feat(bed): prove the desktop serves, and start the session bus it needs

## Summary

`pod-crabbox-desktop` shipped an Xfce-over-TigerVNC lease image with **no
`disposable: true` bed**, so nothing in its gate ever started the desktop. This
adds `check-pod-crabbox-desktop-serves` — a three-step ABSENCE → PERFORM →
PRESENCE R10 bed in the shape of the five sibling lease beds — and fixes the
defect the first run of that bed found.

Closes #2.

**The defect.** The image's documented contract is "Xfce on TigerVNC with a
noVNC web front end, started by `/usr/local/bin/crabbox-start-desktop` over the
lease's SSH session" (`README.md`, `candy/desktop-vnc/charly.yml`). Measured on
a disposable pod built from this tree, the desktop did not start:
`crabbox-start-desktop` launched `vncserver` and `websockify` but established
**no D-Bus session bus**, and a lease has no logind — `pam_systemd` never runs,
so there is no `XDG_RUNTIME_DIR`, and Arch compiles `dbus-launch`'s X11
autolaunch out. `xfce4-session` needs the bus to start *any* of its clients, so
the lease served a black 1920x1080 root carrying one "Unable to contact settings
server" dialog:

- no `xfwm4`, no `xfdesktop`, no `xfce4-panel`, no `xfsettingsd`;
- the framebuffer sampled **47** colours against **602** for a working session.

The fix is in the starter, which is the only thing that owns a lease's session:
it creates the runtime dir, starts `dbus-daemon --session` itself, exports the
address to `vncserver`, and stops the bus in the same trap that stops the
session. A build-scope `check:` (`desktop-vnc-session-bus`) now asserts the
wrapper carries that, so the claim is never prose-only.

**The bed.** `check-pod-crabbox-desktop-serves`:

1. **ABSENCE** — the instruments exist (`Xvnc`, `vncserver`, the starter, the
   pinned noVNC web root, `sshd` as PID 1), the state is reset, then the desktop
   is proven NOT to serve: nothing listens on 5901 or 6080, an RFB probe gets no
   banner, an HTTP probe gets no answer, and the lease still **refuses** the
   freshly generated key over SSH.
2. **PERFORM** — the read-only `/crabbox` inputs are written temp+mv, the image's
   own shared bootstrap consumes them (the `bootstrap.sh` it supplies writes a
   marker the bed reads back), and `crabbox` starts `crabbox-start-desktop`
   through the lease's OWN SSH path on 2222, detached from the channel.
3. **PRESENCE** — the RFB server answers with the framebuffer the TigerVNC
   config pins (1920x1080) and that framebuffer carries a **rendered** desktop;
   noVNC's web root answers over HTTP on loopback 6080; the websockify proxy
   forwards the same server's RFB banner; the session bus and every Xfce client
   it starts (session manager, window manager, desktop, panel, settings daemon)
   run in display `:1` as the lease user; both listeners are loopback-only; and
   the lease still holds over SSH as `crabbox` with passwordless sudo and
   `/usr/local/libexec/crabbox/ready` exiting 0.

The RFB and WebSocket probes are spoken from inside the lease on purpose: both
listeners bind 127.0.0.1 inside the container and neither is published, so the
org's host-side `vnc:` verb has no endpoint to dial (it resolves a VM's graphics
device) and would SKIP — and a skipped step is not a proof. The colour threshold
is 200, separating the two measured states (47 vs 602) by a factor of four.

The bed deliberately does not claim the containerd lease venue
(opencharly/charly#1109 — the same scope its five siblings claim), the
Docker-compatible socket, or the Wayland alternative the image installs but
never starts.

## Change classification

An image-behaviour fix in one variant's starter plus a new disposable bed. A
consumer that already exports its own `DBUS_SESSION_BUS_ADDRESS` keeps it; a
consumer that does not now gets a working session instead of a black screen.

**Breaking change + rollback:** none for consumers — `crabbox-start-desktop`
keeps its name, its port mapping (127.0.0.1:5901 / 127.0.0.1:6080), its
loopback-only bind and its "started over SSH, never the entrypoint" shape; it
gains one child process (the session bus) which is stopped with the session.
Rollback is reverting this commit, which returns the wrapper to launching
`vncserver` without a bus and makes the new bed red again.

## Filed issues

- opencharly/pod-crabbox#7 — *A lease guest has no machine-id or
  XDG_RUNTIME_DIR, so D-Bus autolaunch can never start a session bus.* Found
  while proving this bed: the base image ships neither, so anything relying on
  `dbus-launch` autolaunch fails (`Failed to initialize Xfconf: Cannot spawn a
  message bus without a machine-id`). **Non-blocking here** — this image's
  starter now starts the bus explicitly, so the desktop lease works without the
  base fix, and the base repo is the right owner.
- opencharly/pod-crabbox-desktop#3 — *The VNC framebuffer carries only the top
  half of the configured screen.* Reproducible at 1920x1080 and 1280x800, at
  depth 24 and 32, with and without the xfwm4 compositor, while
  `_NET_DESKTOP_GEOMETRY` reports the full size. Present with and without this
  change, so it is not introduced here; the bed's PRESENCE asserts a rendered
  desktop (which it is) and this is filed as a separate defect with the ruled-out
  matrix and the next probe.
