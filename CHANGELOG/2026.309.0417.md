# 2026.309.0417 — feat(image): add the desktop lease image pod-crabbox-desktop

## Summary

Adds `pod-crabbox-desktop`: the desktop lease image for the Crabbox `containerd` provider, one of the `pod-crabbox-<variant>` images tracked by opencharly/opencharly#869 (W5.2). It is the pinned `opencharly/pod-crabbox` lease contract plus Xfce on TigerVNC, a noVNC web front end, the Wayland stack, and a loopback-only `crabbox-start-desktop` starter.

- **`charly.yml`** — the image: `import: crabbox: @github.com/opencharly/pod-crabbox:v2026.307.1828` with `base: crabbox.pod-crabbox`, `distro: [cachyos, arch]`, `build: [pac]`, and `user: root` with the inherited direct-mode `sshd -D` entrypoint.
- **`candy/desktop-vnc/charly.yml`** — the desktop layer:
  - the Arch/CachyOS repository packages (`pacman -Si`, 2026-11-05): `xfce4-session`, `xfwm4`, `xfce4-panel`, `xfdesktop`, `xfce4-settings`, `xfce4-terminal`, `xfce4-appfinder`, `thunar`, `dbus`, `xorg-xinit`, `xorg-xrdb`, `xorg-xsetroot`, `tigervnc`, `labwc`, `wayvnc`;
  - noVNC 1.6.0 and websockify 0.13.0 from their pinned upstream releases with `download:` (neither has an Arch/CachyOS package; the URLs are the AUR PKGBUILDs' own source URLs), plus a `/usr/local/bin/websockify` entry point;
  - `/etc/tigervnc/vncserver-config-defaults` selecting Xfce, 1920x1080x24, the loopback bind, and `SecurityTypes=None` (the loopback bind plus the lease's SSH session are the boundary, and `vncserver` otherwise refuses to start without a password file);
  - `crabbox-start-desktop`, which runs `vncserver :1` and `websockify --web /usr/share/webapps/novnc 127.0.0.1:6080 127.0.0.1:5901` and never replaces the entrypoint.

- **`.github/workflows/image.yml`** — the thin caller of the org reusable `image-build.yml`, pinned by commit (`@bd1e195cadfce40e09719d99a16f7353e1aa27bd`): `pull_request`/`workflow_dispatch` build only (a `ci-<sha>` tag, publishing nothing); a successful `tag-on-merge` completion publishes the newest `v*` git tag as the image tag.

### Scope note — the AUR route was measured, abandoned, and swept

The plan row names `novnc` + `websockify`, which are AUR-only on Arch/CachyOS (`pacman -Ss novnc` and `pacman -Ss websockify` are both empty, 2026-11-05). The AUR route was tried first and failed at the builder stage: `charly box build` built `cachyos.arch.arch-builder` and then could not resolve its generated `FROM ghcr.io/opencharly/arch-builder:<this-build-tag> AS desktop-vnc-aur-build` (`not found`). The driver binds only the image's own `ARG BASE_IMAGE` from the charly image store (`candy/plugin-build/imagestore.go`'s `containerfileBaseRef`), so a multi-stage builder's `FROM` is resolved by buildkitd against the registry at this repo's build tag, which is never published — and the imported builder is deliberately not pushed by a variant (`pushOutputFor` excludes `import:`-qualified boxes). The gap is recorded on opencharly/charly#982 (the existing issue for this local-image hand-off class), with this measurement added as evidence.

The image therefore ships noVNC/websockify from their pinned upstream releases (the exact source URLs the AUR PKGBUILDs use), with `build: [pac]` only. websockify's core proxy needs only the Python standard library, which the base image ships. The second commit (`31b0932`) sweeps the abandoned-AUR claims out of the repo prose; the absence grep and the disposition of every surviving mention are pasted below.
